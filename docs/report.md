## KPI ที่ไม่ผ่านและสาเหตุ (พิสูจน์จากข้อมูล)

1. **Thai PBS freshness:** ระบบจด `first_seen_at` แยกดีเลย์ได้ว่า ฝั่งเว็บ (published → ขึ้นหน้ารายการ) median 33.2 นาที ฝั่งเรา (เห็น → เก็บ) median 0.3 นาที เช็คถี่ขึ้นแก้ไม่ได้
2. **YouTube p95 67.9 นาที:** รันทุกชั่วโมง + search index ดีเลย์ คลิปที่เข้า index ช้าถูกเก็บรอบถัดไปด้วย overlap 15 นาที (แลกกับการไม่ตกหล่น)
3. **YouTube videos 98.86%:** ขาด duration 141 snapshot จาก 39 วิดีโอ ตรวจผ่าน API แล้วเป็นวิดีโอตั้งเวลาฉาย (`upcoming`) ยังไม่มีความยาว
4. **Thai PBS 22 req/นาที:** burst จาก Playwright โหลด JS หลายไฟล์ในการเปิดหน้าเดียว และตัวนับรวมไฟล์จาก cache จึงสูงกว่าภาระจริง

## ปัญหาที่เจอและการแก้

| ปัญหา | การแก้ |
|---|---|
| ข่าวสดตอบ 403 ตอนเผลอรันบอทซ้อน 2 ตัว | หยุดทั้งหมด พัก 2 ชม. เพิ่มตัวกันรันซ้อนด้วย heartbeat |
| Docker crash วนจากบั๊กพิมพ์ผิด ทุก restart ยิงเว็บใหม่ | แก้บั๊ก, เสนอ `restart: on-failure:5` |
| ปิด VS Code แล้วบอทตายเงียบ ไม่มีแจ้งเตือน | ย้ายไปรันใน PowerShell แยก, เสนอ dead man's switch ภายนอก |
| งบ YouTube ต่อรอบเกิน เพราะ query แรกกินหมด | ดึงหน้าแรกทุก query ก่อน (test จับได้) |
| ข้อมูลผิดแม้ test ผ่าน: category encode ซ้อน, ` - ข่าวสด` ท้ายหัวข้อ, ข่าวที่เกี่ยวข้องปนในเนื้อหา | decode ซ้ำ, `title_suffix`, `content_selector` + stop marker พร้อม regression test |
| ข่าวสดได้ 403 เฉพาะใน Docker | ยังตรวจสาเหตุอยู่ รัน 24 ชม. บน Windows แทน |

## สิ่งที่จะทำต่อ

กำหนดจำนวนขั้นต่ำให้กฎแจ้งเตือน parse · ข้ามเช็ค latency รอบแรกหลังเริ่ม · ลด burst ของ Thai PBS (เปิด `/news` เฉพาะใกล้เที่ยงคืน) · หยุดยิงเว็บเองเมื่อได้ 403/429 · เก็บ `liveBroadcastContent` ของ YouTube
